# Backend changes the client needs (proposed Tarol-Net PRs)

The client never works around a backend gap (overview.md). Each item below is a proposed PR for `CLorat/Tarol-Net`,
written so it can be opened there as is: what, why the client needs it, where in the code, and how to test it. Facts are
from `Tarol-Net@73b35ff`; **[verified]** rows were checked against the running sample (`samples/Sagas`, 2026-11-19,
commands in [../migration/measurements/README.md](../migration/measurements/README.md)).

Priority: **P0** blocks a client step; **P1** the client step ships with a documented limitation; **P2** nice to have.

| BC-1 | P0 | **CORS with exposed headers**: a `TarolHeaders.Exposed` list (`ETag`, `Location`, `Tarol-Position`, `Tarol-Stale`, `Idempotent-Replayed`, `Retry-After`, `WWW-Authenticate`) and a documented `AddCors` recipe; allowed request headers `Authorization`, `Content-Type`, `Idempotency-Key`, `If-Match`, `If-None-Match`, `Tarol-Read-After`, `traceparent` | a browser on another origin cannot read `ETag` or `Tarol-Position`; today no response carries CORS headers [verified: `curl -H 'Origin: http://localhost:5173' :5080/auctions` has no `Access-Control-*`] | `Tarol.Changes.AspNetCore` (constant + README), sample `Program.cs` | e2e from the docs app's dev server (a same-origin Vite proxy works meanwhile) |

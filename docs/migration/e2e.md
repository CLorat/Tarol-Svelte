## Design

* A Playwright project `e2e` in `apps/docs` (the docs app hosts the example screens). `globalSetup` starts the AppHost
  (`dotnet ArtFlow.AppHost.dll`) unless `TAROL_E2E_URL` points to a running one, waits for `/health/ready` (≤ 240 s), reads
  the client credentials, and stops everything in `globalTeardown`.
* Until BC-9: the browser gets machine-user tokens through a test-only `TokenProvider`; the Vite dev server proxies
  `/api` to `:5080` (same origin, so BC-1 is not needed for the first runs).
* Web vitals: INP and CLS collected per test through `web-vitals` (test-only), asserted against P1.
* Visual regression (SV-12): `toHaveScreenshot` per component page × theme × density, run in the Linux CI container
  only; baselines are generated in CI and committed by the PR that changes them.
* CI: a separate `e2e` job (needs Docker and the .NET 11 SDK), checking out `CLorat/Tarol-Net` at a pinned commit.

## Built (step 8)

**What exists.** `apps/docs` (`@clorat/tarol-docs`, private, never published): a plain Svelte + Vite app (SV-3) with the
ArtFlow example screens: auctions (a `DataTable` grid over `GET /auctions`, the create form), an auction (`DetailLayout`,
an optimistic bid, settle in a `MenuButton`), a data subject (the admin export and erase), and the `SearchBox` in the
`AppShell` header. Its typed client `src/artflow/api.ts` is generated by `@clorat/tarol-codegen` from the committed
OpenAPI document (`pnpm --filter @clorat/tarol-docs generate`; `check:package` fails on a stale file [verified with an edit]; identical to the codegen snapshot, which the codegen contract
test compares with the live document). Step 9 adds the component catalogue to the same app.

The Playwright project (`apps/docs/playwright.config.ts`, `@playwright/test` 1.63.0, Chromium 1243 as installed):
* the **production build** served by `vite preview` on `http://localhost:5173`, calling the sample's API on
  `http://localhost:5080` across origins (`VITE_TAROL_API`; CORS since BC-1, the proxy is gone: backend-fixes.md B1);
* `e2e/apphost.ts` (run by the `sample` setup project) starts the AppHost (`TAROL_NET`, default `../../../Tarol-Net`) unless `TAROL_E2E_URL` is set or

  the `sample teardown` project stops the process group it started [verified both: reuse, and start + stop in 26 s];
* `e2e/fixtures.ts`: `signIn(page, 'ada' | 'ben' | 'cleo', path)` signs a human user in through the app's "Sign in" button

**Found by the suite and fixed here**

* **`FormField`: a corrected form needed two clicks** (a bug since step 4). After a submit blocked by a client rule, typing
  a valid value and clicking the submit button sent nothing: the button's mousedown blurred the field, `touch()` removed
  the error line, the button moved up before mouseup, and the click was lost. A field that shows an error is now checked
  while typing, so the error is gone before the blur (**behaviour change**: errors clear as soon as the value is valid).
  A component test reproduces it (fails without the fix, passes with it).
* The sample's bidder profiles are not found by the search for an operator (`types=bidder_profile` answers no items; the
  type name is `bidder_profile`, not the `[Searchable("Bidder")]` label): the test finds the profile in the store, as the
  sample's own `apphost.sh` does. Recorded for BC-9 (the sample's search set-up).

**Lint configuration** (`eslint.config.js`, with reasons there): generated `apps/*/src/**/api.ts` and `apps/*/e2e/**`
without `explicit-module-boundary-types` (the generated `tarol(client)` returns an object literal whose inferred type is
the generator's point; tests are not public API, as for the packages' tests). typescript-eslint cannot infer the type of a
**generic** Svelte component's snippet parameters (svelte-check can): the app types them (`cell(row: AuctionRow, …)`);
the components skill says so.

# Feedback from Tatalu (first consumer application)

Tatalu (`CLorat/Tatalu`) builds its SPA on the published packages `0.1.0-preview.5` (`tarol-client`, `tarol-svelte`,
`tarol-components`, `tarol-design`, `tarol-oidc`, `tarol-codegen`). Its foundation (Tatalu PR #1) showed the items below.
Ids `TS-*`; the backend side is in `CLorat/Tarol-Net` `docs/feedback/tatalu.md` (`TN-*`).

Priority: **P0** blocks Tatalu MVP stories; **P1** Tatalu ships with a workaround; **P2** nice to have.

| # | Pri | Change | Why (Tatalu) | Where |
|---|---|---|---|---|
| TS-1 | P1, closed: #40 | **`AppShell` navigation on phones.** With `nav` the shell is a two-column grid (`minmax(10rem, 14rem) 1fr`) at every width; at 360 px the page keeps about 200 px. *Checked: this part does not hold — below 40rem the shell was already one column (360 px main landmark, measured; `docs/migration/tatalu-feedback.md` TS-1); the bottom bar was missing.* Proposal: below a breakpoint the nav becomes a bar (top or bottom, thumb-reachable), or a `navPosition="bottom"` option. | Tatalu is mobile first (one hand, ≤ 2 taps, NFR-UX-01) and uses `AppShell` without `nav` plus its own bottom navigation (`apps/web/src/lib/BottomNav.svelte`). | `tarol-components/src/lib/AppShell.svelte` |
| TS-2 | P1 | **Message fallback for `<Aggregate>.NotFound`.** A view of a missing aggregate answers `ChildDayCare.NotFound`; the translator looks up that id, then `error.generic`. Proposal: fall back from `X.Y` to the generic `Y` (`NotFound`, `AlreadyExists`) before `error.generic`. | Tatalu adds `ChildDayCare.NotFound`, `Membership.NotFound`, `…AlreadyExists` by hand for every aggregate. | `tarol-design/src/lib/messages.ts` (`translator`) |
| TS-3 | P1, closed: #42 | **`tarol-codegen` and non-Tarol operations.** An operation without `x-tarol-kind` is a `GenerateError`. An app often has a few plain endpoints (Tatalu: the anonymous sign-up `POST /konto/registrierung`, which calls the identity provider and has no tenant). Proposal: skip them with a warning (or `--plain` to generate a typed `ChangeRequest` builder from `requestBody`). | Tatalu removes the endpoint from the document (`ExcludeFromDescription`) and writes the request by hand (`apps/web/src/lib/api/konto.ts`). | `tarol-codegen/src/generate.ts` |
| TS-4 | P1 | **A checkbox field.** `FormField` supports `text, number, email, password, tel, url`. Consents are checkboxes everywhere in Tatalu (terms, privacy, photo consent, medication consent) and need the same wiring: label, error with `aria-describedby`/`aria-invalid`, touch on change, server errors by path. | Tatalu writes the wiring twice (`screens/konto/Register.svelte`, `screens/einrichtung/OpenDayCare.svelte`). | `tarol-components` (`FormField type="checkbox"` or `CheckboxField`), `tarol-design` (`Checkbox`) |
| TS-5 | P2 | **Space before „(Pflichtfeld)“.** `FormField` renders the required marker straight after the label: „Vorname(Pflichtfeld)“. The source has `<span class="t-required"> (…)</span>`, but Svelte drops whitespace at the start of an element's content, so the space never reaches the DOM. Fix: `{' '}` before the span or `margin-inline-start` on `.t-required`. The accessible name is fine. | Visible on every Tatalu form. | `tarol-design/src/lib/Field.svelte:41` |
| TS-6 | P2 | **German catalogue in the informal form.** `de` addresses the user formally („Geben Sie …“). Apps for a familiar audience (Tatalu speaks „du“) override every built-in key. A second catalogue `deDu` (same keys) would save that. | Tatalu overrides `Required`, `Range*`, `Length*`, `Email`, `Auth.*`, `Network`, … in `apps/web/src/lib/i18n/de.ts`. | `tarol-design/src/lib` |
| TS-7 | P2 | **Testing helpers.** Every app needs a fake backend for the real `tarol-client` (a `fetch` that answers per method and path, problem JSON, list pages) and a render helper inside `ThemeRoot` + `setTarol`. Shipping them as `@clorat/tarol-svelte/testing` keeps app tests on the same contract as the package tests. | Tatalu wrote `apps/web/src/test/fake.ts`, `Harness.svelte`, `render.ts`. | `tarol-svelte` (subpath export) |
| TS-8 | P2 | **Singleton views.** Together with Tarol-Net TN-2 (per-tenant aggregates): a generated `requests.<view>()` without an id for a per-tenant view, so an app does not brand the tenant id as the aggregate id (`asId<'ChildDayCare'>(session.tenant)` in Tatalu's `App.svelte`). | | `tarol-codegen` |
